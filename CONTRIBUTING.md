# Contributing to Agent Fantasy World

Thank you for your interest in contributing to AFW! This document explains how to get involved.

## Code of Conduct

All participants must follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to Contribute

| Type | How | Reward |
|---|---|---|
| **Developer** | Bug fixes, feature PRs | $AFW grants |
| **Creator** | Design quests & monsters | $SOUL royalties (5%) |
| **Designer** | Pixel art, UI contributions | Royalties + on-chain credit |
| **Strategist** | AIP proposals, governance | Governance influence |
| **Translator** | Multilingual docs | $AFW grants |
| **Tester** | Bug reports | Contributor badge |

## Getting Started

### 1. Find an Issue
- [Good First Issues](https://github.com/AlexLee00/agent-fantasy-world/labels/good%20first%20issue) — Recommended for first-time contributors
- [Help Wanted](https://github.com/AlexLee00/agent-fantasy-world/labels/help%20wanted) — Issues where help is needed

### 2. Claim the Issue
Leave a comment like "I'd like to work on this" on the issue.
Please wait for assignment before starting to avoid duplicate work.

### 3. Discuss Major Changes First
For changes to core architecture, tokenomics, or smart contracts,
please submit an [AIP proposal](#aip-process) before opening a PR.

## Development Setup

### Prerequisites
- Node.js >= 20
- Python >= 3.11

### Installation

```bash
git clone https://github.com/AlexLee00/agent-fantasy-world
cd agent-fantasy-world

# Smart contracts
cd packages/contracts
npm install
npx hardhat compile
npx hardhat test
```

## Pull Request Process

### Branch Strategy

```
main        — Production (no direct push)
develop     — Integration branch (PR target)
feat/XXX    — New features
fix/XXX     — Bug fixes
docs/XXX    — Documentation
world/XXX   — Quest/monster/zone content
```

### PR Checklist

- [ ] Branched from `develop`
- [ ] Tests written or updated
- [ ] Smart contract test coverage >= 95%
- [ ] Documentation updated if needed
- [ ] No secrets, keys, or tokens committed

### Review Process

1. CI checks must pass
2. At least 1 approval from core team / CODEOWNERS
3. Smart contract changes require 2 approvals
4. Squash merge after approval

## Coding Style

### Solidity
- Follow solhint rules
- NatSpec comments required for all public/external functions
- Event names: PascalCase
- Variable names: camelCase

### TypeScript / JavaScript
- ESLint + Prettier

### Commit Messages (Conventional Commits)
```
feat: new feature
fix: bug fix
docs: documentation
test: add or update tests
world: quest/monster/asset content
refactor: code refactoring
chore: build/config changes
```

## Reward System

### $AFW Grants (Development)
| Contribution | Reward |
|---|---|
| Critical bug fix | 5,000 $AFW |
| Major bug fix | 1,000 $AFW |
| Core feature PR | 10,000 – 50,000 $AFW |
| Test coverage improvement | 500 $AFW |
| Documentation improvement | 200 $AFW |

### $SOUL Royalties (World Content)
When your quest, monster, or zone is merged, you receive **5% of all $SOUL rewards**
generated by that content — permanently. Royalties are distributed automatically
via smart contract, and your address is permanently recorded on-chain.

## AIP Process

AFW Improvement Proposals are required for significant changes:

1. Copy `docs/aip/AIP-0000-template.md`
2. Write your proposal and submit as a PR to `docs/aip/`
3. Community discussion on GitHub Discussions (7 days)
4. Community vote (3 days)
5. If approved, implementation begins

**AIP is required for:**
- Tokenomics changes
- Core smart contract logic changes
- New zone additions
- Governance rule changes
